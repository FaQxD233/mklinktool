# mklinktool：Windows 目录迁移与链接工具

## 用途

这是一个 Windows PowerShell 5.1 桌面工具，可把多个来源目录复制到选定目标，再在原位置创建目录符号链接（SymbolicLink）。目标副本校验完成、链接可访问后，才会清理同级源备份。

本仓库保留了 2026-09-27 已完成迁移的操作记录。工具没有预设或自动扫描那些目录；不要用历史目录作为验证数据。

## 启动

双击 `migrate-local-folders.cmd` 后会打开唯一的普通权限主窗口。把资源管理器中的一个或多个文件夹直接拖进窗口或来源列表即可；拖放只导入路径，不会复制或移动文件。首次执行需要管理员权限的操作（通常是第一次点击“扫描并预检”）时，工具请求一次 UAC 并启动隐藏的提权 Worker；之后的预检、迁移和清理共用该 Worker，直到主窗口关闭。Worker 意外退出后再次操作时可能需要重新确认 UAC。任务发出后如果没收到 Worker 的确认，界面会保持锁定并说明原因，等任务确实结束后再解锁。工具只创建目录符号链接 `SymbolicLink`（对应 `mklink /d`）。引擎会先创建临时测试链接检查能力；检查失败就不会开始复制。

项目不需要安装第三方模块。GUI 和迁移引擎均使用 Windows 自带的 Windows PowerShell 5.1、WinForms 和 Robocopy。

**启动失败时的提示**：启动器以隐藏窗口运行 PowerShell。窗口出现之前出错（例如缺少组件），会弹出“目录迁移工具启动失败”的对话框，写明原因和出错位置；脚本根本无法运行（文件损坏导致语法错误，或组策略强制的执行策略不允许运行脚本）时，弹出标题为 mklinktool、以 “mklinktool could not start.” 开头的对话框（启动器 `.cmd` 只能用英文，正文是系统自带的中文错误信息）。若提示与执行策略有关，而文件是从网上下载的，可在文件属性中“解除锁定”，或请管理员调整策略。

主窗口启动时会做两项检查：

- **工具目录权限**：提权 Worker 和引擎直接从工具目录加载脚本。如果当前用户、Administrators、SYSTEM、TrustedInstaller 之外的账户或组能修改这些脚本或目录，窗口顶部会显示红色安全警告；悬停可查看具体账户和修复办法，同样的内容也写在日志区，可以选中复制其中的命令。详见下文“安装位置与安全”。
- **中断的迁移**：如果上次迁移在“源目录已改名为备份、尚未创建链接”时被断电或强制结束，会提示是否把备份改回原路径（需要管理员权限）。详见“中断恢复”。

PowerShell 5.1 文件系统提供者支持 `SymbolicLink`；微软文档说明 Windows 创建目录符号链接需要管理员权限，Windows 10 build 14972 及以上的开发者模式可免除。[New-Item 文档](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.management/new-item?view=powershell-5.1)

## 使用流程

1. 选择目标根目录。
2. 选择目标结构：
   - 平铺：`<目标根目录>\<来源目录名>`。
   - 分类：`<目标根目录>\<来源父目录名小写或盘符>-<来源目录名><yymmdd>\<来源目录名>`。例如 `%USERPROFILE%\AppData\Local\Example` 会生成为 `local-Example<yyMMdd>\Example`，`%USERPROFILE%\AppData\Roaming\Example` 会生成为 `roaming-Example<yyMMdd>\Example`；`C:\Example` 会生成为 `c-Example<yyMMdd>\Example`，`C:\Projects\Example` 会生成为 `projects-Example<yyMMdd>\Example`。日期使用运行当天的 `yyMMdd`。
3. 逐个添加来源目录，或从资源管理器一次拖入多个文件夹。来源表格支持 Ctrl/Shift 多选；右键来源路径或目标路径可打开目录、复制路径或移除选中项。表格显示预估文件数、数据量和最终目标绝对路径；目标路径可在表格中修改。
4. 默认使用较快的 Robocopy 结果、相对文件路径、文件数、文件大小和修改时间校验。需要逐文件内容校验时勾选 SHA-256；大目录会明显增加读取时间。
5. 点击“扫描并预检”。来源根重解析点、外部/损坏链接、文件链接和未知重解析点会被拦截；来源内部目标仍位于来源根内的目录 Junction 和目录 SymbolicLink 会作为警告显示，并保留其链接类型。每一项的错误（包括来源/目标互相包含、空间不足这类跨任务冲突）都会以错误图标显示在该行的“状态”列，悬停可查看原因。
6. 检查表格中的内部 Junction/符号链接数量、“状态”列的提示（链接警告与权限提示），再点击“开始迁移”。确认框会说明备份清理选择、绝对链接对原来源根链接的依赖，以及目标权限的处理方式（沿用来源权限，或有几项的目标位置允许本机其他账户写入）。切换“SHA-256 校验”“删除源备份”或“目标沿用来源的访问权限”不需要重新预检。
7. 默认在验证成功后安全清理源备份；取消勾选即可保留备份。清理时先逐项删除备份里的重解析点本身，再删除剩余普通目录树。
8. 迁移在改名前失败或已回滚时，目标位置会留下副本，它会阻止下一次预检（“目标路径已经存在”）。点击“清理失败副本”可删除这些副本；引擎删除前会再次确认来源仍是原路径上的普通目录、没有迁移备份、副本本身不是链接，不满足的项不会删除。

## 迁移过程

每个来源按以下步骤独立处理：

1. 使用 Robocopy `/SJ /SL` 复制文件、隐藏文件、空目录、属性、时间戳，以及目录 Junction/目录 SymbolicLink 本身，不展开链接目标；`/XJ` 不启用。
2. 接受 Robocopy 退出码 0 到 7；退出码 8 或更高时停止并保留源目录。复制完成后，把目标中各项的所有者改回来源中对应项的所有者（见“目标的访问权限”中的“所有者”）。
3. 用手动队列扫描普通目录，不进入链接目标。比较源与目标的相对文件路径、文件数、每个文件的大小与修改时间，以及嵌套链接的相对路径、类型和目标。修改时间在目标卷为 NTFS/ReFS 时精确比较，exFAT 允许 2 秒误差；FAT32 按本地时间保存、跨夏令时会差整小时，因此不比较。勾选 SHA-256 后，再比较每个普通文件的哈希。
4. 将源目录同盘改名为 `<目录名>_migration_backup`。如果目录被占用而不能改名，工具停止该项，原源目录和目标副本都保留。
5. 通过 Win32 `CreateSymbolicLinkW` 创建顶层 SymbolicLink（与预检探针使用同一调用），并检查根链接与嵌套链接的类型、目标路径和目录访问。随后把改名后的备份与复制校验时的来源再比对一次（路径、大小、修改时间、嵌套链接），确认来源在校验之后没有被写入；否则这些改动不在目标副本中，删除备份就会丢失。
6. 建链、验链或这次复核失败时，移除本次创建且目标匹配的链接，再把同级备份改名恢复为原源路径。目标副本保留，可用“清理失败副本”删除。
7. 上述检查都通过即视为该项已提交：此后的任何错误（例如备份清理失败、日志写入失败）都只记录为警告，不会再回滚，避免删除正在工作的链接。随后按设置删除或保留源备份。删除备份时先逐项单点解除嵌套重解析点，并清除只读属性，再递归删除普通目录树。删除失败时活动链接仍指向已校验的目标；提示会说明备份是“未作改动，完整保留”，还是“清理中途失败，剩余内容可能已不完整”（完整数据始终在目标副本中）。

某一项失败后不再处理后续各项，它们在表格中显示为“未执行”。同一时间只允许运行一个迁移、清理或恢复任务（包括多开窗口的情况），后启动的会直接报错退出。

预检会拒绝来源根重解析点、外部或失效链接、文件链接和未知重解析点。来源内部的目录 Junction 与目录 SymbolicLink 只有在目标解析后仍位于来源根内时才会放行；相对符号链接按链接所在目录解析后再检查边界。它也会拒绝已经存在的目标/备份、重复或互相包含的路径、磁盘根目录，并检查目标所在本地固定磁盘空间，在估算数据量之外保留 1 GB。所有来源先完成预检，再开始第一项迁移。

预检还会检查来源实际所在的卷能否在原位置建立链接：必须是本机磁盘上支持符号链接（NTFS、ReFS）且不是只读的卷。FAT32、exFAT、光盘、只读卷，以及网络位置（UNC 共享、映射的网络驱动器，或路径中经过指向网络共享的链接）都会在预检时被拒绝，而不是等全部复制完、到建链一步才失败。网络位置不支持的原因是：链接会建在远程计算机上，远程计算机默认不解析指向本机的符号链接；即使本机允许解析，其他访问该共享的计算机也会把它解析到它们自己的磁盘。可移动磁盘上的 NTFS 卷可以作为来源。

**绝对链接依赖限制**：绝对目标的内部 Junction/SymbolicLink 保留原始目标路径，依赖原来源路径持续作为顶层 SymbolicLink 指向目标目录。如果以后删除或改动该顶层链接，目标目录内的绝对链接会失效。相对 SymbolicLink 会按目标树中的相对布局解析。

### 目标的访问权限

Robocopy 使用 `/COPY:DAT /DCOPY:DAT`，保留文件与目录的数据、属性和时间戳，不复制 ACL 安全权限。默认情况下，目标副本继承目标位置的权限。Windows 在非系统盘（如 `D:\`、`E:\`）根目录下新建的文件夹，默认允许所有已验证用户（Authenticated Users）修改。因此把 `%LOCALAPPDATA%` 这类私有数据迁移到这类位置后，本机其他账户也能读取和修改它们；把会以管理员或服务身份运行的程序目录迁移过去，任何未提权的程序都能替换其中的文件，从而提权。

默认情况下（不勾选下面的选项），预检通过后工具会比较“目标位置会继承的写入权限”与“来源目前的写入权限”：如果 Everyone、Authenticated Users、Users 或 INTERACTIVE 这些宽泛组在目标位置获得了来源没有的写入权限，就在该行“状态”列和确认框中给出权限提示。这只是提示，不阻止迁移。

**选项“目标沿用来源的访问权限”**（默认不勾选）：勾选后，复制前先按来源根目录当前生效的权限创建目标根目录，并且不继承目标位置的权限；其中的文件和子目录再从目标根目录继承，结果与来源中的文件完全一致。勾选后不再给出上面的权限提示。

- 好处：迁移不会让其他账户获得原本没有的权限，私有数据仍然只有原来的账户能访问，程序目录仍然只有管理员能改；也不会收窄权限（例如程序目录原本允许所有用户读取运行，迁到私有位置后其他账户就打不开了）。
- 代价：
  - 来源权限本身不允许管理员写入的目录（例如只有 TrustedInstaller 能写的 `WindowsApps`）会复制失败。失败发生在来源改名之前，来源不受影响，取消勾选即可按原方式迁移；这类系统目录本来也不应迁移。
  - 权限里记录的是本机账户。目标若是外接硬盘、以后接到其他电脑上，那边的普通用户无法直接打开（管理员可以，资源管理器会提示“继续”并改写权限）；不勾选时目标继承“所有已验证用户可修改”，换电脑也能直接使用。
  - 只沿用来源根目录的权限：来源子项上单独设置的权限不复制（不勾选时同样不复制）。
- 建议：从系统盘迁到另一块内置硬盘时勾选；目标是会在多台电脑间移动的外接盘时不勾选。

**所有者**（与上面的选项无关）：目标中的目录和文件由提权运行的引擎创建，默认会归 Administrators 组所有。复制后，引擎把每一项的所有者改回来源中对应项的所有者（例如你本人），这样 Git 等会检查目录所有者的工具可以照常使用：实测在普通权限下，Git 会拒绝打开所有者为 Administrators 组的仓库，提示 “detected dubious ownership”。例外是引擎无权指定的所有者：来源中归 SYSTEM、TrustedInstaller 或其他账户所有的项，以及以另一个管理员账号提权时归你本人所有的项。这些项保持 Administrators 组所有，迁移日志会记下项数。

不使用 Robocopy `/COPY:S` 来复制权限：实测它把来源的规则原样带到目标，但仍标记为“从父目录继承”且不受保护，一旦目标所在的父目录重新传播继承（例如在父目录上修改权限），这些规则就会被父目录的规则取代。

迁移前请关闭正在使用来源目录的应用。工具不会猜测进程与目录的关系；有限重试的 Robocopy 和改名步骤会尽早暴露无法读取或被占用的文件。复制校验之后仍写入来源的改动会在提交前被发现并回滚；但仍打开着文件、在同一大小上原地改写、且修改时间要到关闭文件才更新的写入发现不了，所以关闭应用仍是前提。不同来源不是一个全局事务：某项失败时，之前已成功的项保持成功状态。

## 中断恢复

如果 Windows 在源目录改名为 `_migration_backup` 后、创建原路径链接前关机或终止进程，源路径可能暂时不存在，但源内容仍在同级 `_migration_backup` 目录，校验副本仍在目标目录。

**自动检测**：每次开始迁移前，主窗口会在 `%LOCALAPPDATA%\mklinktool\pending` 写入一份记录。下次启动时，工具会逐项检查记录中的来源：只有“备份目录存在、而原路径上没有任何对象”的项会被列出，并询问是否把备份改回原路径。恢复由提权引擎执行，执行前会再次确认原路径仍为空、备份是普通目录。选择“否”不做任何改动，下次启动会再次提示。已完成、未开始或已恢复的项会自动从记录中移除；记录所属的窗口仍在运行时不会被检查。

**手动恢复**：确认原源路径不存在、且没有其他进程正在操作后，可把备份目录改回原目录名。在确认应用数据可用之前，不要删除目标副本。

如果工具报告自动回滚未完成，优先检查日志给出的备份与目标路径。不要直接清空其中任何一个目录。

## 安装位置与安全

主窗口以普通权限运行。点“扫描并预检”时，它请求 UAC，以管理员身份运行工具目录里的 `migration-worker.ps1`，Worker 再以管理员身份运行同目录的 `migration-engine.ps1`；这两个文件都是在提权那一刻从工具目录读取的。如果本机其他账户（或以其他账户运行的程序）能修改这个目录，就能把自己的代码写进去，你下次在 UAC 提示上点“是”时，这些代码就以你的管理员权限运行。UAC 提示上只显示“Windows PowerShell”，看不出脚本是否被改过。

主窗口启动时会检查工具目录和其中脚本的权限，发现问题时显示红色警告，但不阻止使用：检查代码本身也在这个目录里，能改 Worker 的人同样能改主窗口脚本和启动器、把检查删掉，所以无论警告还是阻断，都挡不住已经发生的篡改，只能在被改之前提醒你。这个问题能彻底解决，办法在安装位置而不在代码：

1. 把工具放在只有管理员能写入的位置，例如 `C:\Program Files\mklinktool`。不要放在非系统盘根目录下新建的文件夹等其他账户可写的位置。
2. 或者把当前目录的权限收紧为只有你、Administrators、SYSTEM 可写。警告里给出了针对当前目录的一行 PowerShell 命令：它把目录权限整个换成这三条完全控制、不再继承上级目录，其中的文件随之继承；收紧后你本人照常可以编辑。目录所有者不是你时会提示拒绝访问，请改用第 1 种办法；之后若仍有警告，说明某个文件单独设置了权限，可对它运行 `icacls "<文件路径>" /reset`。没有改用 `icacls` 收紧整个目录，是因为目录上若有本机无法解析的账户（例如某些沙箱工具添加的条目），`icacls` 会报错且整条命令不生效。

收紧之前要先确认脚本没有被改过，例如重新下载，或在 Git 仓库中运行 `git status`。

“以另一个管理员账号提权”（OTS）时需要注意：主窗口仍以当前用户运行，提权一次后，它在本次会话期间都能让 Worker 对任意目录执行迁移类文件操作，相当于把管理员级的文件系统能力交给了当前用户。只在信任当前用户时这样使用。

## 文件、日志与项目说明

完整的仓库文件索引、运行调用链和代码审查摘要见 [`PROJECT_OVERVIEW.md`](PROJECT_OVERVIEW.md)。

程序运行入口是 `migrate-local-folders.cmd`；主窗口由 `migrate-local-folders.ps1` 提供，提权任务经 `migration-worker.ps1` 转交给 `migration-engine.ps1`。`README.md` 是使用指南，`DESIGN.md` 记录架构与安全决策。以 `PLAN_` 或 `plan-` 开头的文件是方案/实现记录，`operation-notes.md` 是历史迁移记录；这些文件都不是运行入口，也不会自动成为迁移作业清单。`tests\` 是开发用的自动化测试，使用工具时用不到。

每次扫描、迁移、清理或恢复都会在 `%TEMP%\mklinktool-<任务编号>` 留下一个会话目录，里面是任务清单、进度、引擎日志、Robocopy 日志和结果。窗口的“打开日志目录”按钮可直接打开本窗口最近一次的会话。Robocopy 日志只记录出错的文件（带完整路径和原因）与汇总，不逐条列出正常复制的文件。主窗口每次启动时会删除超过 7 天的会话目录。
